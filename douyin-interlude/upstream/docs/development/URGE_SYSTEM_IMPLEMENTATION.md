# Urge 实现与合作检查

2026-09-07；在 HDSI 插件源码原位实现，默认关闭，随 `1.0.0-beta8` 发布。没有修改 typ-0 或桌面数据库。

## 实际链路

真实消息 → 两分钟活跃桶（合并碎片） → 对话结束/延迟回复端点 → 唯一 `automation.nextAdvanceAt`。

自动主叙事 → 正常提交完整原始剧本和既有行动 → 可选 `urge` 原文交接 → 计算下一时间。Urge 不生成独立回复，也不进入事实库、Embedding、Alter 或提示词中的长期状态。

高 Urge + Agency 已批准的实际发送行动 → 等待匹配参与者/剧本条目的首个发送回执 → 有限加速。短时加速不是预写催问，每次仍重新写生活并判断是否联系。无回执不会启动；后续分段回执不会重启加速。通信摘要仍等待全部分段完成。

## Console 配置

`urge.enabled=false` 保持原调度；开启不会替代 `runtime.autoAdvanceEnabled` 总开关，也不会打开 `allowProactiveMessages` 或 Agency。

| 项 | 默认/含义 |
| --- | --- |
| frequency | medium；low/medium/high/custom，custom 未填项用中频 |
| proactiveWillingnessThreshold | 0.4；关闭后仍用 runtime 的原值（默认 0.65） |
| advanced.hotMin/Max、idleMin/Max | 密聊/安静等待范围，分钟；留空按档位 |
| advanced.burstMin/Max、slowMin/Max | 加速首轮/慢节奏范围，分钟；加速后续逐次翻倍 |
| halfLifeMinutes | 45；热度按真实时间衰减 |
| burstThreshold / jitter / extremeChance | 0.75 / ±0.15 / 0.03；随机只作用于调度 |
| burstTtlMinutes / burstBudget | 35 分钟 / 最多 3 次额外续写；不被自动写作重置 |
| burstContactMinMinutes | 5 分钟；只对有效加速段所属对象覆盖普通 Agency 联系间隔 |

高级项均位于 `urge.advanced`。所有时间范围可手动覆盖，包括预设档位；上下界倒置时按最小值收敛，非法旧值使用安全默认值。

低频 hot 20–30、idle 60–90、burst 5–10、slow 120–180；中频 10–20 / 35–55 / 3–7 / 110–130；高频 6–12 / 20–35 / 2–5 / 90–120 分钟。实际唤醒有现有后台扫描粒度及前台写作排队误差，不承诺精确秒级触发。

## 历史与部件冲突表

| 对接点 | 处理与边界 |
| --- | --- |
| 旧 SQLite/knowledge 空对象 | 不改表、列、knowledge 或用户数据；urge 使用现有 extensions JSON，读取 null、{}、错数组、缺字段、未知版本均有兜底。原 knowledge 修复不动。 |
| 固定 10/20 分钟后续 | 开启时清空并停止消费旧后续队列，只保留一个下一推进时间；不是两套并行 timer。 |
| 开关/档位热重载 | 下次后台处理检测配置签名，清旧加速并重排一次；同配置重启直接使用已保存时间，不反复抽签。关闭后恢复普通间隔，下一次真实对话恢复旧后续计划。 |
| 暂停/恢复 | 继续使用原暂停与串行队列；过期加速不补跑多轮，至多以当前窗口续写一次。 |
| 新消息/多参与者 | 只有真实用户事件计热度；任何新消息终止旧加速段，防止另一关系收到旧加速。热度是共享主角的会话活跃度，加速联系间隔按目标隔离。 |
| 延迟/分段消息 | 保留原投递和中断路径；延迟端点重设调度但不加热度；投递回调不调用 Urge 模型。 |
| 未回应悬念 | 可继续保留在剧本中；已启动的联系段耗尽后不自行重新启动，须新真实对话打开下一段。 |
| 意愿/Agency | 归一化和 Agency 共用有效门槛；普通间隔只在对应加速段临时缩短，隐私/设备/负荷/渠道资格仍成立才可联系。Agency 关闭时仍可弹性调度，但不启动需要其批准的联系加速。 |
| slow/休息/Preplan | slow 与休息优先，取更长等待；软 Preplan 不缩短这两者，普通热度节奏仍可对齐 Preplan。硬到期意图继续原队列。设备不可用/超负荷停止联系加速，但自身生活可继续。 |
| intent-due/失败 | 有原文的到期主叙事可交接；narrative-retry 属于用户回合补偿，不生成 Urge。失败无新剧本则不更新；沿用已有重试，不重抽时间。 |
| 原文/记忆/提示词 | 仅增加自动主叙事的可选、正向调度交接；不改核心剧本提示词与原文预算。匹配不到原文的字段忽略，不因此重试主模型。 |
| 写库异常 | 可选 Urge 交接保存失败会告警，不吞掉已提交的发言；这不是对磁盘/权限类 SQLite 错误的修复。 |

## 验证与成本

实现前基线：264 项回归全部通过。实现后：280 项全部通过（新增 16 项 Urge 测试）；严格 TypeScript 检查与 Yakumo 本地构建通过。构建仅提示现有 Vite CJS API 弃用警告，无构建错误。

新增测试覆盖旧形状、JSON 往返、提示词隔离、热度衰减、回执匹配、加速额度、低值、slow、休息、设备、重启过期、Console 校验以及真实 service 方法的调度/关闭/延迟端点、首条回执激活与完整摘要分离、slow 不走软 Preplan、其他状态/重试字段保留。Service 测试使用内存数据库替身；没有对生产 SQLite 执行写入或迁移测试。

每个故事最多 120 个两分钟活跃桶；不扫描历史、不增加 embedding 或独立 Urge 模型。调度日志包含档位、原因、下一时间及本段已用额度。成本增量来自更频繁的原主叙事和时间导演；预算只约束加速段，不限制正常对话或真实到期任务。

尚需实机验收：开启中频，密聊约 15 分钟后静置，确认调度先快后慢；观察一次自然主动联系的回执与后续加速；睡眠正文返回 slow 后确认长等待；切回关闭确认原调度。局部回归不能证明模型会稳定选择恰当的 Urge，也不能证明真实平台发送及长时间拟真度，未擅自调用付费模型或给用户发测试消息。
