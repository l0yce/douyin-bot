## 性能与模块协作

- 历史补齐按 story 单任务运行。模型请求在故事串行锁外执行；完成后在锁内重读源记录，合并最新 metadata，再写 embedding 与指纹。删除或正文已变的记录不回填旧结果。保留同时写入的投递账本。
- 单轮开始 20 秒后不再发下一次历史补齐请求；**这不是在途请求的强制总超时**，单次仍服从 embedding 原有 timeout。空向量／请求失败退避 60 秒，失败档案不前移游标。
- 历史向量冷加载使用同一 promise，避免第二个调用误把尚未装载完成的缓存当作就绪。分句索引随原文缓存复用，源删除／清理仍走原有失效机制。
- 无消息召回相同分支、查询、排除项、来源优先项及源集合短暂复用 60 秒；新增记录或原文缓存失效会重查。每个故事只保留一个后台召回结果，不形成另一套记忆数据库。
- 用户轮最多 3 段、每段约 4,000 字符，沿用原上限；长锚点不再无限突破段落预算。时间导演新增的历史材料标记为旧原文摘录，而不是新事件或当前承诺。
- 原有 P0 联系证据链、投递取消／分段、消息绑定、Alter、Preplan、overlay 与原始剧本保存流程不做替换。事实向量补齐仍有自己的原额度，本轮历史请求预算不等同于整个插件所有模型请求的总预算。

## 数据兼容与限制

游标存入 `story.state.extensions.historyBackfill`；新向量指纹存入 entry metadata。未加新表，不清洗旧事实、旧剧本或旧工作细节。无指纹的既有向量暂时保持旧兼容行为，再按历史额度补齐；已知指纹与当前模型不符的向量不参与语义排序，字面与来源导航继续可用。因此不能断言所有旧向量已验证来自同一模型。

分句索引只提升字面细节召回；完全不同措辞的跨段语义匹配仍依赖整段向量，不等价于多向量细分检索。对特别长且没有标点的句子，只能给有位置说明的局部窗口。来源位置基于提示词可见文本的 UTF-16 字符位置：剧本原文保持原样，已发送消息仍保留原有媒体占位符显示投影。

后台事项查询优先到期 intent 和有依据的 unresolved topic，并非把所有工作细节、全部剧情弧、所有未来计划一起塞进查询。这样控制上下文与不相关回忆，不进行全量自主联想。

## 验证

- 原有 253 项回归及新增 10 项测试：**263 / 263 通过**。
- 严格 TypeScript 检查和 Yakumo 编译通过。只更新本地构建产物，没有生成 tgz。
- 新增测试覆盖：超过 4,000 条历史的游标覆盖；批量为 1／重启续跑／模型改变；单任务与失败退避；并发投递 metadata 保留；同事项改名、跨主体拒绝及旧修订防复活；长剧本尾部／无标点长句；公共后台召回与缓存失效；模型指纹与冷加载并发。
- 6,000 条模拟历史、本地单次记录：首次约 141 ms，复用索引约 9 ms，带 1,536 维向量排序约 18 ms；测试过程堆增量约 36 MiB。不是严格内存占用测量，也不包含真实数据库读取、网络和生成延迟；不据此承诺实机 SLA。
- 尚未进行真实模型连续对话验收或桌面长时运行。安装后的观察重点：旧事项是否交接而不抹掉条件；后台回忆是否只作历史；旧记录覆盖是否随整理轮次增长；主回复延迟与补齐请求量是否稳定。
