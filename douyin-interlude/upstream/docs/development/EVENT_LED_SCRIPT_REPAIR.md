# 事件优先的剧本续写修正

2026-09-07；随 `1.0.0-beta8` 发布。

## 背景

凌晨实机剧本出现了稳定的“解释用户 → 评价用户 → 两条短消息”结构。问题不在投递器：对应的原始剧本本身已连续采用同一理解和收束方式。修正保持剧本中心，不删除原文、不随机打散消息，也不以时间间隔降低细节。

## 本次三个边界

1. **事件先于倾向**：用户消息进入原始剧本时，主模型先辨认它在此刻具体澄清、修正、限定、邀请或保留了什么；关系倾向随后提供细微语境。因而纠正可以得到纠正，问题可以保留未知，普通陪伴也不必被升级成固定关系戏码。
2. **Alter 是天气，不是写法**：侧端分析只描述有近期原因、能自然消退的能量、注意力、节奏、开放或收束条件。主提示词明确让当前事件和现实生活选择行动与段落形态；Alter 不提供对话惯例、人格标签或格式模板。
3. **学习的是可复现的关系选择**：关系发展必须有用户真实反馈和主角随后实际发出的回应；一段场景中的 provisional 候选留作审计和后续对照，但不回传压缩模型。跨场景证据或已应用的候选才会成为可参考的软倾向。

## 不做的事

- 不禁用“吐槽”、短句、分段或既有角色口吻；它们在具体场景中依然可以自然发生。
- 不把关系发展改为手动审核，也不删除既有提案或原始剧本。
- 不引入额外模型调用、相似度重写或一个独立回复系统。

## 验证

新增测试确认事件重估提示存在、Alter 保持状态隔离、单场景 provisional 候选不回灌、无真实反馈的关系提案不创建。全量 `node --import tsx --test test/*.test.ts`：283/283 通过；严格 TypeScript 检查通过。

实机验收重点：同一观影场景中，纠正、共同疑问、玩笑、沉默和实质讨论应能自然形成不同的剧本入口与聊天长度；不要只统计是否还出现两个消息泡。
