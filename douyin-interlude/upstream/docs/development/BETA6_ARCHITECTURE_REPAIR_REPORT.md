# 1.0.0-beta6 五项架构修复报告

日期：2026-09-06。范围：HDS Interlude 插件源码、测试、文档和发布包。没有安装、重启或改写默认 Desktop/typ-0，也没有清洗运行数据库。依据为此前只读审计的 2026-09-05 M10 晚间记录；下午 M8 提交错误不归为 M10 新问题。

## 实现结果

### 1. 同一剧本行动连接发言与执行

主模型在正文的自然发言位置写 `<say id="r">原话</say>`，即时 transport 使用 `actionId:"r"`。解析器只移除标记并保留字词，已有发送器读取同一原话；原话在历史回忆中出现过也不会妨碍绑定到本次行动。正文内一次引用可以包含既有分隔符，仍按原来的气泡顺序发送。

无效/重复标记 id 不触发猜测发送；没有 actionId 的旧 content 输出仍兼容。延迟发送仍是未来草稿。实验性提前流式模式继续使用 content 协议，已经发出去的话不被后到正文改写。不因为文学复用而拒绝整个回合。

已提交正文没有发送事件时，执行证据明确记录 `no-outgoing-action-recorded`。主叙事、导演和整理据此区分“作者写到发送”与“实际有发送行动”；完整投递、部分投递、失败与取消仍由原 segment 账本确认。关系隔离继续生效。

实时模型不再另写 continuitySnapshot；有原始剧本时不再注入旧 snapshot。后台 scene/arc 摘要、历史召回、事实与未决事项保留。新增 memory 带宿主 sourceEntryId，并明确是派生材料，不是执行证明。

### 2. 时间导演交接实际原文，而非自证计划

最新完整原文继续进入导演，有限的其它条目优先保留末端。新记录的 `narrativeAuthority=original-v2` 区分新旧语义；其 timelinePlan 在后续上下文中是 proposedTimeline，不是完成事实。主模型可以在宿主时间窗口内自然推进自己的生活，实际通信仍取决于观察事件与发送器。

计划 carry 不再直接写成下一轮持续状态；导演最后一拍不再覆盖 scene.summary。新 lifeHandoff 只引用本次原文的实际末端。旧自动条目仍使用旧 ledger 约束，不改写历史，也不把旧错误跳时正文重新认证。

未决联系继续存在于原文、事实、承诺和意图中。用户说“启动游戏”可以成为角色惦记、猜测或再次询问的原因，但不应成为“未来数小时用户一直在游戏”的宿主断言。

### 3. 场景按事件交接，不按时间降精度

lifeHandoff 的地点、末端活动、在场表、转场及已完成事项均带本段原文 quote。原文不存在的 quote 不进入索引；此校验只证明来源存在，不冒充模型语义判定。

地点/明确局部转场替换旧在场与活动；完整在场表可表达有原文支持的独处。没有可见来源的旧人物不再作为当前在场证据。新局部边界和事项完成记录保留来源版本，防止较早启动的后台整理重新写入旧同学或已完成事项。新事项有较新证据时仍可使用同一标签。

状态信封 v4 只增加来源版本信息，无新数据库表。剧情弧 ID、既有未决联系、历史原文和检查点保留；没有按时长、消息数或语言相似度强行关闭剧情弧。

### 4. 简化续写入口

续写书签指向上次完成正文的末端和本次新消息来源。主提示要求新事件改变当前理解/注意/行动，再自然进入发言或沉默；已有房间、姿势和上次动作不用重新演一遍。短句应承接实际前因，角色仍可以误解，但实际用户反馈能够修正先前解释。

不裁剪生成正文、不设置重复率拒绝、不增加改写重试，不按时间间隔压缩剧本精细度。原本的 24K 近期原文预算、召回和两种 payload 顺序保留。旧关系笔记标为“主角先前理解”，而非用户态度的确定事实。

### 5. 学习互动变化，区分理解与接收

后台整理新增 interactionEvidence 来源链：前次实际发言、用户原始反馈、主角叙述解释、实际回应。关系 statePatch 可填写 interactionReview；只有 supported 且反馈/回应来源类型、顺序、关系分支正确时，才允许继续晋升。

未提供、unresolved 或 contested 的 review 不增加独立场景置信度，也不直接应用关系倾向。候选仍可保存观察，不把一次反馈强制改成人设。原跨场景、跨日、冷却和反证退场条件继续执行；模型仍需正确理解反馈，宿主不会用“撒娇/不喜欢”等关键词做语义判决。

## 模块合作检查

| 功能 | beta6 接口变化 | 保留行为 |
| --- | --- | --- |
| 私聊/群聊/跨关系 | 正文 actionId 先解析，随后复用旧规范化 | 目标许可、群意愿、引述、分段和延迟 |
| M6 投递/承诺 | no-action 证据补齐；实际气泡仍回写同一事件 | 完整送达才结算，失败/取消/部分送达不算兑现 |
| Director / Schedule Preplan | 区分建议与新原文、保留旧账本解释 | 时间窗口、计划非事实、失败重试、原文最新承接 |
| SceneFrame / 后台整理 | 引用式局部交接与来源版本 | 剧情弧与完整原文不重建；旧后台结果不能覆盖新局部状态 |
| 学习 / Overlay | 用户反馈和实际回应进入证据审查 | 不把临时情绪直接固化，不改旧 overlay 兼容读取 |
| Alter / Agency | 合入已完成的同来源累计对齐；复用原行动门 | 不新增情绪原因相关性衰减，不强制联系或强制沉默 |
| 图片/语音/贴图/浏览 | 仍走原事件与平台行动分支 | 本轮不改外部适配器或调用策略 |

## 验证与边界

本地严格类型检查通过；全量 **243 项自动测试通过**（包含 40 轮确定性连续剧本夹具，不是 40 轮真实模型测试）。`yakumo build hds-interlude` 成功，构建运行时版本为 `1.0.0-beta6`。构建仅有现有 Vite CJS API 弃用提示，不影响产物生成。

自动回归包含旧功能测试以及 beta6 专项：同字多处出现的行动绑定、重复/无效 id、延迟/提前流式兼容、群聊与跨关系分段、M10 20:18 虚构发送注解、普通/cache-first 证据一致、新计划与旧账本分流、局部场景切换、原文引用校验、后台 scene.summary 所有权和反馈学习来源链。

测试使用本地确定性夹具与模拟 provider，不使用真实人物历史作自动清洗，也没有进行付费真实模型回放。通过它们证明接口、状态和兼容路径的行为，不证明模型从此不会复写、误解或幻觉。source quote 校验不是语义真伪检测，旧模型输出仍可能走 legacy content/unbound 兼容路径。

安装后应对照观察：

1. 30–50 轮高密度交谈后，剧本是否仍从上段完成点接演，而非改写整段。
2. 用户明确表达不喜欢时，角色理解与后续学习是否吸收真实反馈。
3. 长沉默中是否完成自己的活动，并保留可再次询问的联系悬念。
4. 正文提及发送时，实际通信证据是否一致；未发送不能再成为已发送摘要。
5. 转场、重启与后台整理交错后，局部人物/事项是否仍正确，跨日事件与剧情弧是否可召回。

当前版本只打包；安装目标需要用户另行指定，不能用 typ-0 工程代替默认 Koishi Desktop。
