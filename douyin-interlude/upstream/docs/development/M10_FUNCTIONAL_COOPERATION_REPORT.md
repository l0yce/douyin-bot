# 1.0.0-beta5-m10 功能合作与闭环检查

历史基线：本报告记录 M10 当时的检查，不代表 beta6 的新时间交接与学习入口。当前实现见 [beta6 修复报告](BETA6_ARCHITECTURE_REPAIR_REPORT.md)。

日期：2026-09-05。范围：当前插件源码、V2 设计、生产入口与调用链、自动化测试和发布包。未安装或重启 Koishi Desktop，未改动运行数据库，未访问 typ-0 工程，未调用真实模型/OneBot/浏览器等外部服务。

## 判断

不能把“所有功能都有入口”写成“所有功能已经被真实调用且组合必然更拟真”。功能应在相应场景和开关下参与，而不是每轮全部启动。本次证实了若干真实对接缺陷并修复；单一剧本主链、原文、来源索引、关系隔离及现有平台发送器保持不变。

本轮检查发现并处理：任务 ID 漏传、前台误消费其它执行器的任务、承诺提前结算、无新消息却产生感知来信事件、关系摘要串入其它私聊跟进、侧端视觉与提示词互相矛盾、分段/浏览开关与写作提示不一致、混合到期队列阻塞已确定气泡、后台人物倾向因空查询完全不参与。

## 承诺投递闭环细节

- commit 记录本次消息对应的承诺登记/结算草稿，但不因此变更承诺完成状态。
- 同一消息事件的全部气泡都确认为 delivered 后，先处理旧承诺解决，再登记新承诺，避免“旧承诺尚占两项上限而新承诺丢失”。
- failed、pending、cancelled、partial 均不触发结算；新消息打断末段不假装用户已收到整段结论。
- 后台通信摘要同样等待当前关系的完整消息确认；两个分段执行入口都补上尾段确认后的摘要登记，摘要记录异常不打断投递主链。
- 明确延期记录 resolutionEventId，避免重复确认反复延期；新承诺记录 originDeliveryEventId，原承诺完成后也不会由旧回调重新创建。
- 不再因“本轮随便发了一句话”而自动完成所有待答承诺。未结算到期项沿既有20分钟策略保留重查；前台处理中也避免同一待办立即抢跑。
- 当前不是完整持久 Outbox/事务性工作流重写。平台接收与数据库落账之间的进程崩溃仍存在不确定窗口；不能保证跨进程 exactly-once。记录失败保持日志与待处理状态，不盲目重发。该限制保留为独立的恢复验收项。

## 提示词轻度优化

保持剧本为唯一主叙事，消息为剧本事件。仅澄清执行现实：原生图片数不等于是否有侧端视觉证据；无新来信的 seen 为 false；分段开关/自定义分隔符与浏览模式使用真实运行配置。后台仍允许联系悬念、期待、再问和暂时放下；不按沉默时长降低原文精细度，不以“禁用主动联系”修复重播。

cache-first 先继承完整基础 payload 再替换历史视图，降低新增字段漏传风险。七组结构仍保持相同消费者位置；不会把历史文本变成新事件。私聊跟进只接收自己的后台通信摘要，独立生活仍可看到简短的关系联系后果。
