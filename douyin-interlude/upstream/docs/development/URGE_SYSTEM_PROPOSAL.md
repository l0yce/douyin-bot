# Urge System：剧本驱动的弹性自动推进

状态：2026-09-07，已随 `1.0.0-beta8` 发布，默认关闭。实现边界与兼容检查见 [URGE_SYSTEM_IMPLEMENTATION.md](URGE_SYSTEM_IMPLEMENTATION.md)。以下保留设计意图，具体行为以实现记录为准。

## 1. 定位

Urge 是 HDSI 内核的可选调度层。它决定下一次何时续写，以及一段时间内续写的频率；角色是否联系、联系谁、说什么，仍由当前原始剧本中的行动决定。

启用后，替代普通固定推进间隔及固定的对话后 10／20 分钟补写计划，统一生成一个 `nextAdvanceAt`；关闭后恢复现有调度。真实消息、已安排的投递、到期意图仍按各自事件进入原有主链。剧本原文、时间连续性和写作精细度不随推进频率改变。

语义约定：用户提到的“自动联系医院”按“主动联系意愿”理解；“Urge 很低时密度不变”解释为**不额外触发 Urge 加速**，密度带来的基础间隔仍随时间恢复。

## 2. 三个输入，各自负责一件事

| 输入 | 来源 | 作用 |
| --- | --- | --- |
| 对话热度 `density` | 宿主统计真实用户消息形成的对话轮次／活跃时间桶 | 密聊结束后较快续写，随后平滑恢复常态；拆成多条的同一段消息合并计数，角色自动发言不增加热度。 |
| 联系冲动 `urge` | 仅在自动触发的主叙事中，结合前文和本次剧本同时输出 0～1 | 与已成立的主动联系行动结合，形成短时密集续写；它不是愿意发送的概率，也不是永久人格指标。 |
| 节奏提示 `pace` | 同一主叙事输出 `normal / slow`，可附建议等待分钟数 | 主角睡觉、专注或暂时不会发生转折时，安排更长的下一次续写间隔。 |

用户对话轮只更新热度，不生成新的 Urge。自动触发的生活推进、对话后余波续写可生成；有主叙事的 intent-due 可生成，单纯定时投递回调不生成。不额外调用一个“Urge 模型”。

## 3. 默认频率档位与手动覆盖

以下数值是初始调参建议，单位为分钟，实机后再校准；档位只改时间参数，不改角色性格或主提示词。

| 档位 | 密聊刚结束 | 热度消退后 | 短时 Urge 推进 | `slow` 默认 |
| --- | --- | --- | --- | --- |
| 低频 | 20～30 | 60～90 | 5～10 | 120～180 |
| 中频 | 10～20 | 35～55 | 3～7 | 约 120 |
| 高频 | 6～12 | 20～35 | 2～5 | 90～120 |

每次调度只抽取一次随机间隔并保存；调度扫描、失败重试和应用重启不会反复抽签。热度建议用最近约 15 分钟的活跃程度估计，离开对话后以约 30～60 分钟半衰期衰减：

`基础等待 = 常态等待 - 热度 × (常态等待 - 密聊等待)`

热度为 0 时回到本档常态，为 1 时接近密聊间隔。每条用户消息只更新固定大小的计数状态，不扫描整部剧本。以本轮对话完成／实际延迟回复交接为计时锚点，正在生成回复时不并发开启自动续写。

## 4. Urge 如何让“很想联系”自然出现

主模型先承接完整原始剧本并写本次生活、想法和联系行动，再附带少量调度字段。例如：

```json
{
  "urge": {
    "value": 0.82,
    "pace": "normal",
    "basisQuote": "她把刚写好的消息发出去，还是忍不住想再问一句。"
  }
}
```

`basisQuote` 是本次已提交正文中的原句，供调度溯源；联系对象沿用现有 proactiveContact／发送行动的目标，不再引入第二份联系决定或第二份消息文本。静默自动推进也可输出 Urge，但没有成立的联系行动时不进入联系加速。

宿主记录模型基础值 `u`，再抽取有效值 `uEff`。建议一般在 u 附近作小幅偏移（默认 ±0.15），可配置低概率的全区间抽样来容纳偶尔特别高／低的结果；抽样只作用于后续调度，不改正文、willingness、既有承诺或对用户的认识。

当 `uEff ≥ burstThreshold`（建议初值 0.75），且本次主叙事通过既有主动联系裁决并形成可执行行动时，建立一个短时加速段。第一段联系得到发送成功回执后激活后续短间隔；失败／等待确认不作为“已经联系过”的证据，交给原投递机制处理。

例如中频密聊结束后 14 分钟续写，剧本自然发出一次主动联系，Urge 较高；后续可能在 4、8、16 分钟后再续写，然后回到密度决定的常态。**每次续写都可以继续自己的生活，也可以再次联系；短间隔不是预排多条催问。**

加速强度从本段开始时刻衰减，不能被自己的自动推进／发言重新充满。后续新的 Urge 可收束或调整剩余节奏；同一段未获回应的联系不因再次抽到高值而无限重开。建议以约 20～40 分钟有效期及可配置的额外推进额度控制调用量，参数用于调度，不要求模型写固定次数、固定语气的催促。真实新对话到来后回到对话链，重新建立对话热度。

`uEff` 低于阈值时不触发短时加速；连续低值不积累“迟早必须联系”的债务。用户沉默可以保留剧本里尚未解决的联系悬念，但不会凭空增加热度、共同约定或联系动作。

## 5. `slow` 与模型建议时间

自动主叙事可输出：

```json
{
  "urge": {
    "value": 0.12,
    "pace": "slow",
    "suggestedDelayMinutes": 120,
    "basisQuote": "她关掉床头灯，把手机放远，准备睡了。"
  }
}
```

宿主将建议限定在用户所选档位／自定义范围，再加入适度随机量。`slow` 表示下次检查可以更晚，不代表已经睡过两小时，也不提前补写未来事实。建议只在当前生活阶段内有效，下一次真实事件会重新裁决。

睡眠／设备不可用时，生活状态与 Agency 优先；即使残留高 Urge，也不进入联系加速。真正到期的承诺、投递或日程边界仍可更早唤醒相应处理；软性 Preplan 不应不断把明确休息重新压成短周期。到时继续用完整原文承接长窗口，不按间隔降低剧本精细度。

## 6. 与当前功能的关键衔接

- **联系阈值**：Urge 开启时有效 willingness 默认 0.4，用户可覆盖；关闭后使用原 `runtime.proactiveWillingnessThreshold`。Urge 与 willingness 独立：随机高 Urge 不会让无意联系的角色强行发言。所有主叙事／跨关系发送检查共用同一个有效阈值函数，防止一处放行、另一处仍按 0.65 拒绝。
- **普通联系的 60 分钟门槛**：当前 Agency 的 `minimumProactiveIntervalMinutes` 默认 60。建议在合格的 Urge 加速段内，对本目标使用显式可调的 `burstContactMinMinutes`（中频初值约 5 分钟），其余情形仍按原门槛；隐私、设备、负荷和渠道资格照常决定行动。否则只会频繁续写而不能再次联系。
- **已有调度统一入口**：替换 `scheduleConversationFollowUpsAfterTurn`／`scheduleNextAutomaticAdvance` 的间隔决策，输出给现有 `automation.nextAdvanceAt`，不并行增加第二个 timer。到期 intent 与 proactive-check 使用现有队列去重，同一唤醒不重复生成。
- **原文与记忆**：Urge 状态、随机种子、到期时间属于调度元数据；不写入事实库、Embedding 记忆或 Alter 累计素材，不训练出“高 Urge 就是人格”的自我强化。
- **暂停／重启／切换**：paused 停止自动生成；恢复后至多处理当前一次待续写，不补跑一串过期加速。关闭 Urge 即重建普通下一时间；密度按真实时间继续衰减。后台调度按故事保存，联系加速按参与者归属，避免跨关系传染。
- **失败与性能**：只有已提交成功的自动主叙事才更新 Urge；模型失败沿用现有退避。新增判断为本地常数级计算；费用主要来自更多的主叙事及其既有导演调用，需展示预计频率、实际次数和最近调度原因。

## 7. 最小配置与实现顺序

配置：`enabled` 默认 false；`frequency` 为 low／medium／high／custom；允许手动设置密聊／常态／加速／slow 的时间范围、热度半衰期、`burstThreshold`、随机强度、加速有效期／额度、`proactiveWillingnessThreshold` 和 `burstContactMinMinutes`。界面先展示开关、档位、联系阈值，其余折叠为高级设置。

1. 建立独立、可注入时间与随机源的 `urge.ts` 纯调度模块；验证热度衰减、持久化随机结果与开关回退。
2. 接入唯一自动调度入口，启用后接管现有固定对话后补写；测试真实用户到来、延迟回复、休息、暂停和 intent 不冲突。
3. 给自动主叙事增加 Urge／pace 的正向写作交接，引用已提交原文；接入发送回执后激活与 Agency 有效联系间隔。
4. 最后增加档位和诊断显示，做密聊→短期联系→安静生活→睡眠的连续实机对照。测试高／低极值、同一悬念无反馈、多参与者、失败与重启；确认原文不变形、不会自发造出用户消息，也不会把频繁调度等同于频繁发送。

首版完成标志：关闭时保持原有行为；开启后密聊自然缩短下一间隔，沉寂自然放慢，剧本中的真实联系冲动可带来有限的短期密集续写，睡眠能返回较长等待；用户能从一条调度记录看清本次为什么在这个时间继续。
