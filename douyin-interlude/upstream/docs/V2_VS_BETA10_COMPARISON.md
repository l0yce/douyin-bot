## 2. 逐功能对比清单

### 2.1 ScriptCommit：从平行字段到原子提交

- **beta10**：模型输出 `script`（叙事 prose）与 `interaction.reply`（回复文本）两个协议字段。提示词要求两者一致，但数据库、拆分发送、失败处理分别操作它们，一致性问题缺乏系统层的校验点。
- **现在**：宿主侧 `commit-builder`（`src/script/commit-builder.ts`）将模型输出编译为 `ScriptCommit`（`src/script/contract.ts`）：commitId / eventId / sceneDelta(proseAppend) / 事件数组一次生成，事件表由宿主填写。平台发送的文字逐字来自剧本内的 outgoing-message 事件。
- **技术收益**：剧本与回复共享同一数据结构，因果链可在数据层验证。示例：用户问"晚上还去看电影吗"，commit 中同时包含 prose（她的心理活动与动作）、一条 outgoing-message 事件（"看呀，七点老地方"）、以及两者的引用关系（`causedByEventIds`）。
- **拟真性收益**：每条平台消息都能在同一 commit 中定位感知、动作、发送的完整因果（`script-commit-adapter.test.ts`、`delivery-ledger.test.ts` 覆盖该性质）。

### 2.2 投递账本（M6.1）：投递结果进入世界状态

- **beta10**：消息发送结果对故事世界不可见。QQ 端投递失败时，剧本中"已发送"仍作为事实存在，后续剧情基于未完成的投递继续。
- **现在**：每个已提交行动在同一 script entry metadata 内建立投递账本（`src/script/delivery-ledger.ts`），按 segment 回写 `pending | delivered | partial | failed | cancelled`；私聊、群聊、拆分气泡、贴图、原生表情、群反应共享 commitId/eventId 身份；成功结果优先级高于较晚的记账错误，部分群失败在汇总状态中保留（M6 异常边界修复）。
- **示例**：三条拆分气泡中第二条被平台拒绝时，账本记录 `partial`（首条 delivered、次条 failed、末条 pending），后续剧情将这一结果纳入她的体验——对方只读到开头。
- **拟真性收益**：投递结果成为后续叙事的输入。承诺兑现绑定完整投递确认（beta5-m10）：失败、取消或仅送达首段时，承诺保持待兑现状态。

### 2.3 原始剧本主权（M4.1）与续写锚点（beta5-m9 / beta6）

- **beta10**：上下文中的"过去"由摘要、SceneFrame 尾句投影和时间账本混合构成。模型每轮读取的"上一幕"为转述层，长故事中的细节在多轮转述间逐渐偏移。
- **现在**：`recentScript` 为原始剧本原文，作为第一权威（`SCRIPT AUTHORITY` 提示条目）。续写锚点（`src/script/continuation.ts`）引用可见原文的末次已完成段落与真实通信条目；场景检查点（`src/script/continuity-checkpoint.ts`）按连续前缀推进，保留完整证据序列。
- **示例**：三天前剧本原文写过"她把伞放在了玄关第二个格子"，当前轮的 recentScript 仍以原文携带该句，模型可让角色今天早上再次经过它。
- **拟真性收益**：长故事中的细节以原文精度跨日保持，跨日事件、埋设的细节与未完成动作都能按原文回到当前回合。

### 2.4 SceneFrame / DialogueBurst：场景身份由生活变化决定

- **beta10**：场景边界由消息数量和时间间隔隐式驱动；连续聊天时地点、姿态、情绪被逐轮重设。
- **现在**：SceneFrame（`src/script/scene-frame.ts`）从既有证据确定性投影为只读场景脚手架；DialogueBurst 由话题、关系范围和明确事件边界推进。帧不保存私聊/群聊 prose 措辞，共享剧本中的跨关系信息按来源隔离。
- **示例**：同一房间里的连续十条消息共享同一个 frameId，地点、在场人物、进行中的活动保持稳定；切换到她出门买菜时，明确的边界事件生成新 frame。
- **拟真性收益**：高密度对话从尚未写出的变化继续（beta3-m6），情节产量由事件密度决定；连续消息不再逐轮重铺场景装置。

### 2.5 写作框架：事件密度导向的叙事分辨率

- **beta10**：主合约要求"每轮 400–700 字自成一体的一幕，无时间跳跃"。该约定下，较短的现实窗口同样被填充至目标体量，且模型倾向于产出形态完整、收束整齐的段落。
- **现在**：`Let narrative resolution follow event density rather than elapsed time`——在感知、选择、身体反应或关系变化处展开，在平淡过渡处简写；快速交换推进小连接拍，稀疏间隔让日常流过。体量随内容自然分布，多样性通过"读取 recentScript 中已用过的形状并尝试不同写法"的正向引导实现，宿主侧无结构检测。
- **示例**：三分钟的等待可以是一百五十字的走神；一个下午的独处可以用七百字承载三件事——体量由该窗口内实际发生的变化决定。
- **拟真性收益**：叙事节奏与现实时间窗口对齐，段落形态随生活内容变化。

### 2.6 主提示词：正向续写支架

- **beta10**：提示词以现实性合约与多条禁令（时间、格式、ChatRhythm 反定型指令）构成；写作问题的历史处理方式是追加反例条目。
- **现在**：七段式正向支架（SCRIPT AUTHORITY / FIELD MAP / 续写锚点 / 未决联系 / 事件密度 / 阶段指令 / 输出协议），以"如何继续生活"为主线。验证器（`src/script/validator.ts`）执行结构校验，文学风格不属于拒绝规则。
- **拟真性收益**：提示词的主体描述生活本身的惯性（未决联系、待办、独立活动），表达变化从人物状态中条件化产生，提示词规模随版本收敛。

### 2.7 knowledge 证据关系（beta7-enhanced）：事实携带认识论属性

- **beta10**：事实为一句裸文本。"她答应周末去万松园"与"她觉得自己大概会去"在存储上同构，整理器的反复叙述可能将推测逐步固化为事实。
- **现在**：事实与工作细节携带 `knowledge` 结构（`src/script/knowledge-evidence.ts`）：mode（观察/转述/信念/提议/条件/确认/未分类）+ holder（认知主体）+ clauses（逐条原文引用，来源条目可验证）+ relatedFactIds（同一事项的事实链）。确认类记录须引用真实的提议与回应交换；置信度提升需要新增来源证据，重复叙述的影响中性。
- **示例**：
  ```json
  { "mode": "proposal", "holder": "protagonist",
    "topic": "万松园",
    "clauses": [{ "role": "proposal", "sourceEntryId": 1204, "quote": "如果电影好看，周末再去一次万松园吧" }],
    "relatedFactIds": [87] }
  ```
  若后续模型写出"她已经默认接受了"但仅有主角视角 prose，该记录自动降级为 `interpretation`/`unclassified`，承诺的关闭条件保持开放。
- **拟真性收益**：认知主体、证据类型与原文引用独立存储，误会、期待、条件式约定等剧情形态在数据层获得支撑，并可通过反证回退。

### 2.8 contactThreads 条件来源链（beta7-enhanced / P0-2）

- **beta10**：无对应机制。承诺类事实以孤立文本进入提示词，三天后"如果电影好看的话"的条件语境已从上下文消失。
- **现在**：主叙事与时间导演读取同一条件来源链：原始提议、条件原文与附近实际回应整条保留（预算内），缺失来源显式标注；旧资料经字面相关性和条件线索导航补取，线索仅用于导航。
- **示例**：数周后讨论周末安排时，提示词中同时出现 1204 号条目的原始提议、其中的条件从句、以及当晚 1207 号条目的实际回应，供模型引用或让她主动确认。
- **拟真性收益**：条件式约定长期保持原貌；未决联系作为持续存在的上下文，支持追问、期待、误会与放下等多种走向。

### 2.9 人物发展：受控维度与显式交接

- **beta10**：状态补丁为自由文本路径，单轮情绪可能进入长期人设 overlay；同一事项改名后新旧标签并行（"想睡觉"与"正在游戏"并存），无交接机制。
- **现在**（M8.3 + P1-1）：statePatch 收敛为受控 `development.*` 维度，观察先于结论，跨场景去重后晋升；反证降低置信度并撤下倾向；相关场景最多投影两条来源化软倾向，按关系隔离，与永久 overlay 分离。P1-1 补充同事项显式交接（`replacesLabel`）：改名须援引较新的有效原文证据，新旧修订按来源 entry id 比较。
- **示例**："想睡觉"需由带 `replacesLabel` 与较新原文证据的记录交接为"正在游戏"；仅凭推测的更新不生效。
- **拟真性收益**：性格变化具有跨场景证据要求，变化幅度与证据量相关；单一事件的即时情绪与长期性格在存储层分离。

### 2.10 记忆导航（M7.2 + P1-2/3/4）：分层检索

- **beta10**：单一字面/语义召回，长剧本尾部细节受前 80 词项索引限制；历史向量补齐与新记录共用额度。
- **现在**：episode-index（`src/script/episode-index.ts`）提供可重建的场景导航；P1-2 历史向量按持久化游标分页补齐（新旧额度分配、模型指纹、单任务、失败退避）；P1-3 本地原文分句跨度索引 + 有位置的相邻原文展开（零额外 embedding 调用）；P1-4 主叙事与时间导演按到期事项/未解决主题检索旧原文（后台最多一段约 2,400 字符，无消息回合无实时向量请求）。
- **示例**：到期事项"周末万松园之约"触发检索时，召回的是当时约定的原文段落及其相邻上下文，检索由当前生活中的线索驱动。
- **拟真性收益**：长文本尾部的细节保持可召回；召回内容为原文；回忆的触发与当前事项相关联。

### 2.11 时间导演与时间守卫

- **beta10**（0.1.5-beta7-enhanced/beta10-foresight 时期）：时间导演已有指数退避与熔断；实况守卫经三层修复（开头 30 字叙事宣告位、计划语义豁免、用户背书钟点集合）消除 23 次误杀。
- **现在**：全部保留，并新增 timeline-routing（`src/script/timeline-routing.ts`，M8.1）：短对话后续/到期窗口在无已知结构边界时免调用时间导演；路由只改变模型工作量，prose 解析保持同一管线。cache-first 与 legacy 两种 payload 顺序下时间证据一致（beta5-m9 补齐）。
- **拟真性收益**：守卫区分"叙事时间越界"与"引用用户说出的约定"；导演调用按窗口特征裁剪，长窗口保留完整账本，短窗口节省延迟。

### 2.12 分段回复登记修复（beta7-enhanced / beta6）

- **beta10**：终端显式分段台词（`甲||乙`，或单一 say 标记仅包住首句）中，后续语句存在登记缺失，仅第一句进入发送队列。已确认实例：17:38 的第二句未进入发送队列，表现为用户侧"漏发"。
- **现在**：同一私聊行动的完整分隔块统一进入原有 commit、分段发送与回执链；普通叙述、未来草稿、多目标动作保持原有路径；新消息打断机制维持不变。
- **示例**：剧本写`开心||等等我再看看`，两条气泡按顺序投递并各自回执，第二条的状态在账本中独立可查。
- **拟真性收益**：多气泡的发送节奏与回执完整到达用户侧，每段的投递状态可追溯。

### 2.13 ChatRhythm 模块移除（M9）：反定型职责归位

- **beta10**：独立 ChatRhythm 模块检测表达节奏并以升级措辞注入 payload——检测器判据驱动，注入文本为系统口吻。
- **现在**：检测/指令模块移除（`chat-rhythm.ts` 已删除），气泡节奏由投递链继承，多样性由正向提示框架承担。旧配置隐藏且保持兼容，历史状态原样保留。
- **拟真性收益**：表达多样性来自生活内容差异与正向引导；检测判据的维护成本与误触发路径一并移除。

### 2.14 统一模型路由与 payload 缓存友好序

- **beta10**：`configuredProviders`/`effectiveMainModelId` 分散于 narrator；payload 键序为构建顺序的结果。
- **现在**：`src/model-routing.ts` 统一路由；payload 支持 cache-first 键序（稳定前缀命中服务商前缀缓存，currentEvent 位于末尾 recency 位，新增 recentExchange 块），当前默认使用 cache-first；仍可切回 legacy 键序以兼容旧行为。
- **示例**：cache-first 下 setting/memories/recentScript 等低频层位于前缀，currentEvent 与 recentExchange 位于末尾；长故事运行时前缀缓存命中率随轮次累积。
- **拟真性收益**：稳定前缀缓存降低长故事运行的边际成本，使每轮携带完整原文历史在经济上可持续。

### 2.15 桌面桥接 protocol 4 与 typ-0 协同

- **beta10**：desktop-bridge 投影无 commit 身份，桌面端可见的条目流缺少来源标识。
- **现在**：protocol 4 时间线投影携带 commitId / deliveryActions（投递账本真值）/ sceneCheckpoint；宿主对异常 metadata 形状做防御（`desktop-bridge.ts`）。typ-0 桌面工作台据此呈现每条消息的投递状态与场景检查点。
- **拟真性收益**：对终端用户不可见；为长运行提供可审计的观察面，提升调试与运维效率。

### 2.16 旧数据库兼容（beta7-enhanced 补丁，2026-09-07）

- **beta10 时期遗留行**：beta6 之前写入的 `interlude_fact.knowledge` 列为 `{}`（无 clauses/relatedFactIds），新代码读取路径上的半保护取值在该形状上抛 `Cannot read properties of undefined (reading 'includes')`，主叙事与后台推进随之中断。
- **现在**：存储证据读取统一经 `knowledgeClauses`/`knowledgeRelatedIds` 归一，缺失形状按未分类派生记录处理，数据库保持原样；回归测试覆盖 `{}` 与半缺两种形状。
- **拟真性收益**：既有故事升级后直接可用，旧事实以"未分类"身份继续参与叙事。

## 3. 新架构的整体优势

1. **真相单源**。旧架构的叙事状态分布于 prose、reply 字段、SceneFrame 摘要、时间账本四处，一致性依赖提示词约定；新架构将其折叠进一次原子提交，剧本为唯一叙事真相，其余均为带来源的只读投影。一致性在数据结构层成立。
2. **因果可追溯**。commitId/eventId/sourceEntryIds 使每个可见结果（消息、表情、状态变化、事实）都能定位到剧本内的来源。例如"她为什么发这句话"是数据查询而非文本推断。
3. **失败进入世界状态**。旧架构对失败（投递失败、输出畸形、时间越界）的处理是丢弃重写；新架构将失败编码为世界事实（failed segment、pending 原因、冷却状态），后续叙事以其为输入，角色的体验包含这些结果。
4. **检测收敛为结构**。旧架构对失真的处理以检测器为主（时间守卫枚举、ChatRhythm 判据、字数箱体）；新架构在结构层消解多数检测需求（守卫收敛为"用户背书 + 叙事宣告位"，ChatRhythm 移除，体量交给事件密度）。结构约束的覆盖面由数据模型保证。
5. **认识论分层**。观察、转述、信念、提议、条件、确认独立建模，"谁知道什么、依据什么"成为一等数据。角色的错误信念、条件式承诺与待确认状态在存储层可表示、可回退，支撑误会与和解类剧情。
6. **可持续运行**。稳定前缀缓存、防御性读取边界、可重建索引（episode-index、跨度索引均为派生数据）使长故事、旧故事、多故事场景在成本与稳定性上可长期运行。

## 4. 尚未验收的边界
