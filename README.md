# douyin-bot · 抖音 AI 好友助手

[![公开版检查](https://github.com/l0yce/douyin-bot/actions/workflows/check.yml/badge.svg)](https://github.com/l0yce/douyin-bot/actions/workflows/check.yml)

把 **抖音私信机器人、幕间系统和网页控制面板** 放在一起的项目。

让机器人只回复白名单好友，设置角色的说话方式，参考你手动发过的消息，并在网页上管理聊天、剧情、记忆和运行状态。

仓库只有代码和公开示例，**不包含开发者的账号、Cookie、密钥、私人角色设定、好友名单或聊天记录**。下载后需要配置你自己的账号和模型。

## 能做什么

- **白名单聊天**：按昵称、抖音号和会话身份绑定好友，减少串人或误发。
- **手动聊天协作**：把当前好友会话中可读取的双方消息加入上下文；你手动接话时，可取消机器人等待发送的回复。
- **图片与表情包**：配置图片模型后理解图片；未提供可读取内容的消息会附上说明。
- **视频评论参考**：不播放视频、不提取画面或音频，尝试读取默认排序的前 5 条顶层评论，每条最多 30 字，供模型参考。面板可调整数量、长度、缓存和超时。
- **不可用视频卡片处理**：识别“视频无法查看”等占位卡片，有编号就尝试读评论，没有编号就说明内容不可见，避免把界面提示当成好友原话。
- **幕间系统**：角色设定、持续剧情、记忆、日程和可选主动联系。公开示例默认关闭主动联系。
- **手机管理面板**：查看聊天动态、白名单、日志和状态，在“剧情与记忆”中切换幕间管理、聊天协作与视频评论。
- **QQ 邮箱故障提醒**：持续故障后提醒，带重复提醒间隔和恢复通知。默认关闭，不需要额外调用 AI。

> 抖音网页可能改变页面、要求验证，或不提供某条消息的实际内容。本项目不保证所有卡片和评论都能读取。历史条数指当前网页实际读到的消息，不能保证补全未加载的旧消息。

## 三部分怎么配合

```text
抖音私信 ↔ 机器人（读取、身份校验、发送）
                   ↕ 本机认证接口
              幕间系统（生成回复、剧情与记忆）
                   ↕
              网页控制面板（设置与查看）
```

| 目录 | 作用 |
| --- | --- |
| `douyin-friend-ai-bot/` | Python + Playwright/Firefox，负责抖音收发 |
| `douyin-interlude/` | Node.js 桥接与幕间；`upstream/` 保留引擎源码及许可证 |
| `douyin-bot-panel/` | FastAPI 后端、网页前端、邮件检测 |
| `scripts/` | 初始化、安装和公开发布检查 |
| `deploy/` | systemd 模板和 Nginx 示例 |
| `docs/` | 使用、隐私与验证说明 |

## 部署前准备

安装脚本适用于使用 **systemd** 的 Linux，自动识别 **apt、dnf 或 yum**，分别安装 Python 和 Firefox 所需依赖。推荐 Ubuntu 24.04 / Debian 12；dnf/yum 系统会使用 RPM 依赖安装方案，并在启动服务前检查 Firefox 能否运行。发行版要求和排查见 [Linux 安装说明](docs/LINUX.md)。需要：

1. Python **3.11 或以上**、Node.js **20 或以上**及 npm。
2. 你自己有权使用、能正常登录网页版私信的抖音账号。
3. 兼容 OpenAI Chat Completions 的模型接口地址、API Key 和模型名。理解图片需要支持图片的模型。
4. 能使用 SSH 和编辑 JSON 文件。系统软件源需提供所需依赖，Python 不足 3.11 时需先安装受支持的新版本。

**如果部署在云服务器上，先准备家庭／住宅代理出口。** 本项目原部署遇到过机房 IP 无法正常登录抖音的情况，采用家庭出口访问抖音。代理应让抖音看到家庭宽带的出口 IP；换成另一台机房服务器的普通代理不能达到同样目的。不是所有机房 IP 都必然失败，家庭出口也不能保证免除登录验证。

```text
云服务器上的机器人 → 家庭／住宅代理 → 家庭宽带出口 IP → 抖音
```

需要自行准备可从云服务器连接的家庭出口：可以是自己家庭网络中的转发服务，也可以是自己有权使用的住宅代理服务。仓库不附带代理地址、账号或现成节点。详见 [家庭代理出口的准备与配置](docs/PROXY.md)。

面板需要控制服务，此版安装方案以 root 运行，适合由你独立管理的服务器。不要把面板交给不可信用户。

## 1. 下载并安装

### 1.1 在服务器安装项目和控制面板

本步骤的安装命令在 **Linux 服务器的 SSH 终端**中执行。后面建立访问隧道的命令则在 **你自己的电脑**上执行，注意区分。

先安装 Git，按服务器的包管理器选择一条：

```bash
sudo apt-get update
sudo apt-get install -y git
# dnf 系统改用：sudo dnf install -y git
# yum 系统改用：sudo yum install -y git
```

然后下载项目：

```bash
sudo git clone https://github.com/l0yce/douyin-bot.git /opt/douyin-bot
cd /opt/douyin-bot
# 先安装符合要求的 Node.js 和 npm，再执行下面的脚本。
sudo bash scripts/install.sh
```

Node.js 安装说明见 [官网](https://nodejs.org/en/download)。

可先运行 `bash scripts/install.sh --plan` 查看安装计划，此操作不会修改系统。不要覆盖系统自带 Python；脚本会优先选择已有的 Python 3.11 或以上版本。

脚本会安装 Python 依赖、Firefox、幕间依赖，生成本地私密配置，并启动虚拟显示和面板。**不会自动启动机器人发消息**。依赖下载失败时，按终端报错处理后重跑。现有配置不会覆盖。

### 1.2 确认控制面板安装成功

安装命令结束后，仍在服务器上执行：

```bash
sudo systemctl status douyin-bot-panel.service --no-pager
curl -fsS http://127.0.0.1:8790/api/health
```

看到服务状态 **`active (running)`**，且第二条命令返回 **`{"ok":true}`**，说明面板服务已经启动。面板默认只监听服务器本机 `127.0.0.1:8790`；直接在自己电脑的浏览器输入“服务器 IP:8790”无法访问，这是默认部署方式。

如果服务没有运行，先查看错误原因：

```bash
sudo journalctl -u douyin-bot-panel.service -n 80 --no-pager
```

按报错修复依赖、路径或端口问题后，用 `sudo systemctl restart douyin-bot-panel.service` 重启，再重复上面的状态与健康检查。安装脚本未成功完成时，先解决安装报错，不要直接跳到后面的启动步骤。

### 打开面板

**推荐使用 SSH 隧道，首次部署不需要域名或开放面板公网端口。** 保留现有的服务器终端，另外在自己的电脑打开一个 PowerShell 或终端窗口，执行：

```bash
ssh -N -L 8790:127.0.0.1:8790 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 root@你的服务器地址
```

1. 将 `你的服务器地址` 替换为实际服务器 IP 或 SSH 域名。`root` 是 SSH 用户名；使用其他管理账号时换成自己的用户名。按平时连接服务器的方式输入密码或指定自己的私钥；SSH 端口不是 22 时追加 `-p 你的SSH端口`。
2. `-N` 表示只建立隧道，成功后终端会保持等待，不出现新的命令提示符。**保持这个窗口打开**；关闭窗口或断开 SSH 后，浏览器也会无法访问面板。
3. 在自己电脑的浏览器打开 **`http://127.0.0.1:8790/`**，应看到“访问令牌”窗口。这里的地址是你电脑的本地隧道入口。
4. 回到之前的服务器 SSH 终端，读取面板令牌：

   ```bash
   sudo cat /opt/douyin-bot/douyin-bot-panel/panel_token
   ```

5. 只复制输出的令牌文本，粘贴到网页的 **访问令牌** 输入框，点击 **保存并进入**。这不是模型 API Key、SSH 密码或抖音 Cookie。
6. 进入 **运行状态**，确认右上角显示 **面板在线**，机器人进程在首次安装时显示 **已停止**。此时面板已部署成功，可继续第二步配置；先不要点击“启动机器人”。

这里的 `ssh -L` 用于访问控制面板，与家庭代理出口是两回事。命令中第一个 `8790` 是电脑的端口，第二个是服务器的面板端口。如果电脑的端口已被占用，改用：

```bash
ssh -N -L 8791:127.0.0.1:8790 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 root@你的服务器地址
```

然后访问 `http://127.0.0.1:8791/`，服务器面板端口无需修改。打不开网页时，先确认隧道窗口仍连接、服务器面板健康检查成功，以及浏览器地址与隧道的第一个端口一致。提示令牌无效时，重新读取当前安装目录的 `panel_token`，不要使用其他项目的令牌。

**手机或域名访问（可选）：** 已有自己的 HTTPS 网站时，将 `deploy/nginx.conf.example` 的 `location /botpanel/` 配置加入该网站的 HTTPS `server` 块，执行 `sudo nginx -t` 检查，通过后再 `sudo systemctl reload nginx`。随后访问 `https://你的域名/botpanel/`，输入同一份面板令牌。该配置片段不负责申请证书或创建网站；首次部署可先用 SSH 隧道完成全部配置，不必为此开放 `8790` 或 `18765` 的公网端口。

面板主要入口：

- **聊天动态**：查看最近收到和发送的消息、剧情引擎连接情况。
- **运行状态**：启动、停止、重启机器人，导入 Cookies，配置故障邮件。
- **好友白名单**：发现、添加、启用和停用好友。
- **剧情与记忆**：管理角色设定、剧情、记忆、日程、模型参数、聊天协作和视频评论。
- **运行日志**：排查读取、模型、代理、发送和评论获取问题。

## 2. 填写模型、账号和角色

首次安装先完成下面的账号和模型配置，再打开面板设置角色。后续调整幕间模型和角色时，可直接使用面板。

| 要设置的内容 | 首次设置位置 | 后续可视化入口 |
| --- | --- | --- |
| 自己的抖音号、昵称 | `douyin-friend-ai-bot/config/config.json` 的 `owner` | 当前面板没有编辑入口，仍需修改文件 |
| 基础模型地址、密钥、模型名 | 同一文件的 `ai` | 幕间模型可在 **剧情与记忆 → 完整参数 → 模型中心 → 模型连接** 调整 |
| 角色名字、人设、关系、说话方式 | 可先编辑 `config/persona.md` | **剧情与记忆 → 设定** |
| 登录 Cookie | 按下一步“登录抖音”导入 | 填写账号昵称不能代替登录 |

以下路径按默认安装目录 `/opt/douyin-bot` 编写。使用 SFTP 文件工具，或服务器上已有的文本编辑器打开文件即可；不要修改带 `.example` 的公开模板。

### 2.1 填写你自己的抖音账号

打开 `/opt/douyin-bot/douyin-friend-ai-bot/config/config.json`，找到 `owner`：

```json
{
  "owner": {
    "douyin_id": "你自己的抖音号",
    "nickname": "你的抖音昵称"
  }
}
```

- **`douyin_id`**：在抖音自己的个人主页查看“抖音号”，按实际内容填写。这里填机器人登录的账号，不是好友的抖音号，也不是手机号或 `sec_uid`。
- **`nickname`**：填写这个账号的显示昵称；角色名字可以在后面的设定页单独修改。
- 这些信息用于识别本人、减少会话身份误判，不会让机器人自动登录，也不需要填写抖音密码。

### 2.2 填写首次使用的模型

向你使用的模型服务获取三项信息：**接口基础地址、API Key、准确的模型名**。在同一个 `config.json` 中找到 `ai` 并填写：

```json
{
  "ai": {
    "base_url": "https://api.example.com/v1",
    "api_key": "你自己的 API Key",
    "model": "服务商提供的准确模型名",
    "vision_model": ""
  }
}
```

**上面的两段 JSON 只展示要修改的部分，不是完整配置，不能覆盖整个文件。** 保留原来的 `account`、`whitelist`、`reply`、`interlude` 等内容，也保留 `ai` 内其他参数。JSON 使用英文双引号，最后一项后面不加逗号。

| 字段 | 怎么填 |
| --- | --- |
| `base_url` | 填服务商给出的 Chat Completions 兼容接口基础地址，通常以 `/v1` 结尾；不是服务商官网、登录页或聊天网页。`api.example.com` 只是占位地址，必须替换。 |
| `api_key` | 填该接口对应的密钥。不要填面板令牌、抖音 Cookie 或邮箱授权码。 |
| `model` | 填服务商文档或模型列表中的模型代码，不能只填自己起的名称。 |
| `vision_model` | 可选。填同一接口、同一密钥可调用的图片理解模型代码；没有就保持 `""`。普通文字模型不一定支持图片。 |

这一组基础配置使用 Chat Completions 兼容接口。需要其他接口预设或给不同任务分配模型，可在幕间启动后使用下面的面板“模型中心”。

保存后可检查 JSON 格式（不会调用模型，也不会发消息）：

```bash
cd /opt/douyin-bot
douyin-friend-ai-bot/.venv/bin/python -c 'import json; json.load(open("douyin-friend-ai-bot/config/config.json", encoding="utf-8")); print("JSON 格式正确")'
```

“JSON 格式正确”只表示文件能解析；地址、密钥、模型是否可用，还需在最后启动验证时核对。

### 2.3 通过面板填写角色和聊天风格

1. 按第一步 [打开面板](#打开面板) 的说明登录面板；如果尚未看到 **面板在线**，先完成面板部署和访问检查。
2. 首次安装的幕间尚未启动。完成上面的基础模型配置后，在服务器执行下面的命令，**此时先不要启动抖音机器人**：

   ```bash
   sudo systemctl enable --now douyin-interlude.service
   sudo systemctl status douyin-interlude.service --no-pager
   ```

3. 在面板打开 **剧情与记忆 → 设定**，等到显示 **已读取当前设定**。如果提示剧情服务暂不可用，先检查幕间是否启动，而不是反复点保存。
4. 按下面的表格填写；展开 **配角、地点与表达方式** 可填写更多内容。

| 面板字段 | 建议填写方式 |
| --- | --- |
| **角色名字**（必填） | 机器人聊天时使用的名字，例如“小禾”。 |
| **角色人设**（必填） | 身份、性格、兴趣、生活习惯、接话方式和不知道时如何回答。可以按下面的虚构示例改写。 |
| **世界背景** | 例如“现代日常，通过抖音私信联系”。没有特殊设定就保持简单。 |
| **你们的初始关系** | 这是白名单好友的默认关系。建议“按实际聊天逐渐熟悉，不预设亲密关系”，避免所有好友都被当成同一种特殊关系。 |
| **剧情起点** | 可选。写故事从哪里开始；没有背景故事可留空，不要把虚构经历写成真实发生过的事。 |
| **配角 / 主要地点** | 可选。只有需要角色背景时再填。 |
| **表达方式** | 例如“中文口语，通常一两句；直接接当前话题，不每次都反问，不输出旁白或动作描写”。 |

可参考这份**虚构示例**，替换成你自己的设置：

```text
名字叫小禾，性格随和，偶尔开玩笑，但不刻意卖萌。
平时喜欢游戏和音乐；具体游戏、角色、术语及常用梗由部署者补充背景。
聊天以短句为主，根据对方的话接下去，不连续追问，不写客服式结束语。
不知道的角色、主播和梗可以坦诚询问，不装作已经查过资料。
以实际聊天记录为准，不编造与好友共同经历过的事情。
没有读到图片或视频内容时，不假装看过；视频评论只能作为参考。
```

5. 在 **聊天节奏** 中设置：初次验证可先关闭 **不聊天时，继续推进角色生活**，减少后台模型调用；需要角色生活剧情时再开启，间隔可先保留 **120 分钟**。**允许角色主动给白名单好友发消息** 建议先保持关闭，关闭后仍可回复收到的消息。
6. 点击 **保存并生效**，等到显示 **已保存并生效**；再点击 **重新读取**，核对保存后的内容。仅输入文字或切换页面不会保存。

保存会应用到当前故事并保留已有聊天记忆，不会重新开局。如果提示有消息正在处理，等处理完成再保存。需要更换整套背景时，应先考虑已有记忆是否仍适用。

也可以编辑 `/opt/douyin-bot/douyin-friend-ai-bot/config/persona.md`，作为首次导入和基础回复使用的人设。**面板保存过角色设定后，幕间优先使用面板保存的人设；单独修改 `persona.md` 不会自动覆盖它。** 想保持两种回复模式一致时，请同步更新文件和面板设定。

### 2.4 后续通过面板调整幕间模型

幕间运行后，可以在网页操作，无需手工编辑它的完整配置：

1. 打开 **剧情与记忆 → 完整参数**，等待配置读取完成；需要时点击 **读取当前配置**。
2. 展开 **模型中心 → 模型连接**，再展开已有连接（首次通常显示 `Existing Douyin model`）。先修改已有连接即可，需要多个模型时再点击 **添加一项**。
3. 保持该连接的 **启用** 开关打开。**工作方式** 选择 **通用兼容接口**，协议选择 **通用聊天接口**（Chat Completions）。
4. 填写以下内容：

   | 面板字段 | 填写内容 |
   | --- | --- |
   | **接口地址** | 完整请求地址，例如 `https://api.example.com/v1/chat/completions`，替换成服务商实际地址。**这里与 `ai.base_url` 的基础地址写法不同。** |
   | **接口密钥** | 此连接对应的 API Key。显示“已保存 · 留空保留”时，留空会保留原密钥；需要更换才重新输入。 |
   | **模型名称** | 服务商提供的准确模型代码。 |
   | **用于主叙事** | 主聊天与剧情模型需要勾选，至少保留一个启用且填写了密钥和模型名的主叙事连接。 |
   | **用于记忆压缩 / 用于情绪变化** | 可让同一个模型承担；需要独立模型时再分配给其他连接。 |

5. 其他参数先保留默认值，点击页面上方 **保存并生效**，等到出现 **已保存并生效**。保存会校验配置并重启幕间；若设定页也有未保存修改，先保存或重新读取设定再操作。
6. 图片理解是可选功能。首次部署直接填写 `ai.vision_model` 更简单；后续在面板单独配置时，给支持图片的连接勾选 **用于图片理解**，再展开模型中心的 **图片理解设置**，打开 **启用**，将 **工作方式** 设为 **辅助分析**（sidecar），然后保存。图片模型使用其他服务商时，可新增一个连接并填写它自己的地址和密钥。

**生效范围要区分：** 面板“模型中心”保存的是幕间模型配置，不会反向修改机器人的 `config.json → ai`。保存完整参数后，其中的幕间模型配置优先于基础配置；只改 `ai` 再重启，可能仍使用面板此前保存的模型。关闭幕间后的基础回复仍使用 `ai`。需要两种模式一致时，分别更新两处。

如果你后续通过文件修改基础模型，重启幕间和机器人使它们重新读取；首次部署尚未完成登录和白名单时，先只启动幕间，机器人留到第 5 步通过面板启动。

### 配置家庭／住宅代理出口

这里的目的，是让抖音访问请求从家庭／住宅 IP 发出，而不是从云服务器的机房 IP 发出。HTTP、SOCKS5 只是连接代理的协议，不能说明出口是否为家庭 IP。应先确认代理的最终出口，再导入 Cookie 和检查登录。直接连接已能正常使用的环境可以留空。

在 `config.json` 的 `account` 中设置：

```json
"proxy_server": "socks5://127.0.0.1:1080"
```

HTTP 代理可填写 `http://127.0.0.1:7890`；不使用代理填 `""`。**这里的 127.0.0.1 指运行机器人的服务器，不是你自己的电脑。** 只在电脑上开代理，不会自动让服务器经过它。

**端口区分：`1080` / `7890` 是代理示例端口，`8790` 是控制面板端口。** 代理端口按你实际的代理服务填写；如果代理也在机器人服务器上运行，请避开面板已占用的 `8790`。

该设置用于抖音浏览器和视频评论读取，不会自动用于幕间或基础 AI 模型接口；邮件提醒通过 SMTP 直连。代理服务须已经启动，且服务器能够连接它。修改后重启机器人：

```bash
sudo systemctl restart douyin-friend-ai-bot
```

需要认证的代理、如何检查连接和如何搭建 SSH 转发，见 [代理出口配置与排查](docs/PROXY.md)。示例地址不是可直接使用的公共代理，仓库不包含任何真实代理凭据。

## 3. 登录抖音

### 推荐：在控制面板导入 Cookies

1. 在自己的电脑浏览器登录抖音网页版，确认是 `owner` 中配置的本人账号，并能正常打开私信。
2. 使用你信任的 Cookie 导出工具，复制抖音网站的完整 JSON；也支持开发者工具中完整的 **Cookie 请求头值**，例如 `name=value; name2=value2`。JSON 数组和包含 `cookies` 数组的登录态对象均可自动转换，不要复制整段 HTTP 请求头。
3. 打开面板 **运行状态 → 机器人进程**，点击 **查看连接日志** 右侧的 **导入 Cookies**。
4. 在窗口中粘贴完整内容，点击 **转换并导入**。机器人正在运行时会先停止；校验失败不会替换原文件。其他网站和已过期的条目会被忽略，结果中会明确提示数量。
5. 等到显示已导入的条数，点击 **完成**。窗口会清空 Cookie 文本；它不会保存在浏览器本地，也不会由接口回显。
6. **首次部署**继续第 4 步添加白名单，再按第 5 步通过面板启动。**已有正常部署**可点击 **启动机器人**，再点 **查看连接日志** 核对实际登录情况。导入成功只表示转换和保存成功，Cookie 失效或需要验证时仍需重新登录。

导入会更新 Cookie 文件和浏览器登录态，并在下次启动时替换持久化浏览器中的旧 Cookies。为避免导入后立即发消息，机器人会保持停止；发现好友脚本正在运行时不能导入。

### 备用：通过文件上传

也可将导出的 **JSON 数组**通过 SCP/SFTP 上传为 `/opt/douyin-bot/douyin-friend-ai-bot/state/cookies.json`。Cookie 相当于登录凭据，不能发给别人。上传前先停止机器人。

```bash
cd /opt/douyin-bot/douyin-friend-ai-bot
chmod 600 state/cookies.json
export DISPLAY=:99
export PLAYWRIGHT_BROWSERS_PATH="$PWD/ms-playwright"
.venv/bin/python src/main.py --check-login
```

在具备图形桌面、已安装依赖的机器上，也可使用 `--login-qr` 交互扫码。不要同时让两个进程使用同一个浏览器 profile。登录失效或出现验证时需人工重新登录。

## 4. 添加白名单好友

### 推荐：在控制面板里添加

先完成上面的代理、模型配置和抖音登录，并确保账号已经与目标好友有私信会话。不需要手动抄写 `sec_uid`，面板可以运行发现脚本读取身份信息。

1. 按第一步 [打开面板](#打开面板) 的说明访问网页，输入令牌，点击 **保存并进入**。
2. 打开 **运行状态**。如果机器人正在运行，点击 **停止机器人** 并确认，等待服务状态变为 **已停止**。初次安装尚未启动机器人时可跳过停止操作。
3. 切换到 **好友白名单**（手机底部显示 **好友**），点击 **发现好友**。
4. 在弹出的“发现脚本（只读，不发消息）”窗口点击 **运行**，等待提示 **发现脚本完成**。运行期间不要启动机器人。
5. 在输出中找到目标好友，核对显示名和抖音号，复制该好友的整行 **可复制白名单项：{...}**。复制你自己的实际结果，不要复制文档里的示例身份。
6. 点击 **关闭**，回到白名单页面，点击 **粘贴添加好友**。粘贴刚复制的那一行，点击 **解析并添加**。
7. 核对列表中新出现的好友及右侧开关。开启表示允许回复，关闭表示不允许回复；需要时可展开 **账号核验信息** 检查身份。最后务必点击页面右上方 **保存修改**，等到出现 **已保存** 提示。**“解析并添加”只添加到当前页面，尚未写入服务器。**
8. 添加多位好友时，逐位重复复制、粘贴和解析，最后统一保存。保存后按第 5 步从面板启动，再让该好友发一条新消息验证。

发现脚本只读取最近会话，不发送消息。找不到好友时，先在抖音账号中建立或打开与该好友的私信会话，再重新发现。不要把自己的账号加入白名单。

> 调整已有好友的启用开关后，同样需要点击 **保存修改**。若要暂停所有自动回复，直接在“运行状态”点击“停止机器人”。

### 备用：通过命令行添加

不使用面板时，可在机器人未运行的情况下执行：

```bash
cd /opt/douyin-bot/douyin-friend-ai-bot
export DISPLAY=:99
export PLAYWRIGHT_BROWSERS_PATH="$PWD/ms-playwright"
.venv/bin/python src/main.py --discover-friends --no-ai
```

终端会输出可复制的白名单项，把选中的好友加入 `config.json` 的 `whitelist.friends` 数组：

```json
{
  "name": "聊天列表显示的昵称或备注",
  "douyin_id": "好友真实抖音号",
  "sec_uid": "发现命令输出的会话绑定值",
  "enabled": true
}
```

三个字段都要填写，不能用示例值启动。通过面板复制实际发现结果时，无需再手工编辑这些字段。发现前先停止机器人，避免浏览器 profile 被占用。

## 5. 从控制面板启动项目

完成前四步后，日常启动不需要在终端运行机器人命令。先确认：面板可以正常登录；第二步的模型与角色已保存，幕间服务已启动；Cookies 已导入；至少有一位真实好友已加入白名单、开启开关并点击过 **保存修改**；使用家庭代理时，该代理也已连接。

### 点击启动并确认运行状态

1. 打开控制面板，进入 **运行状态 → 机器人进程**。
2. 点击 **启动机器人**。面板会先启动虚拟显示，再启动机器人。等待页面刷新，不要连续重复点击。
3. 确认进程显示 **运行中**、“已运行”开始计时；必要时点击右上角 **刷新**。进程启动不代表抖音登录已成功，还需继续核对连接与收发。
4. 点击 **查看连接日志**，进入 **运行日志**。确认没有登录失效、代理连接失败、配置错误等报错。发生登录失效时，回到运行状态重新 **导入 Cookies**，再点击 **启动机器人**；代理失败时先恢复代理连接。
5. 打开 **聊天动态**，查看顶部的 **剧情引擎** 是否显示 **已连接**。若未连接，回到第二步检查幕间服务；“启动机器人”按钮不会代替第二步启动幕间。

### 确认好友消息能收到和回复

1. 让一位已启用的白名单好友发送一条新的普通文字消息。
2. 在 **聊天动态** 查看收到的内容及处理结果，等待生成和发送完成。看到 **已发送** 后，再到实际抖音会话核对回复。
3. 首次没有故事时，可在 **剧情与记忆 → 概况** 点击 **启动故事**，按窗口提示点击 **执行**；也可以等白名单好友发来消息后自动建立故事。“启动故事”用于建立角色剧情，与运行状态的“启动机器人”用途不同。
4. 没有回复时，先看聊天动态的状态，再到 **运行日志** 查看原因。幕间可能根据上下文选择暂不回应，不能只凭进程“运行中”判断收发成功。

### 后续启停

- **停止收发**：在 **运行状态 → 停止机器人** 点击并确认，等待显示 **已停止**。面板仍可访问；幕间是否继续推进生活由设定页的开关控制。
- **恢复收发**：点击 **启动机器人**。
- **重新打开机器人浏览器**：点击 **重启** 并确认，再查看连接日志。
- **更新登录信息**：点击 **导入 Cookies**。导入完成后机器人保持停止，需再次点击 **启动机器人**。

安装器已为面板和虚拟显示设置开机启动，第二步也为幕间设置了开机启动。**面板的“启动机器人”只启动当前进程，不会修改机器人的开机自启设置。** 按本教程首次部署后，服务器重启时可以重新打开面板，再点一次“启动机器人”；当前开机自启状态可在机器人进程卡片中查看。

## 可选：QQ 邮箱提醒

在运行状态中填写自己的发件 QQ 邮箱、收件邮箱和 **SMTP 授权码**。授权码不是 QQ 登录密码，需要在自己的邮箱设置中开启 SMTP 后获取。

保存并成功发送测试邮件后，开启提醒，在服务器执行：

```bash
sudo systemctl enable --now douyin-fault-alerts.timer
```

默认持续故障 3 分钟才提醒，间隔 120 分钟重复提醒，并支持恢复通知。邮件通过 SMTP 直连，避免抖音代理故障阻断提醒。检测器运行在同一台服务器上，**整台服务器断电或断网时无法发送邮件**。
